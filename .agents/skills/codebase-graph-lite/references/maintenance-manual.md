# 維護手冊指引

功能完成、提交 PR／MR 前，在專案的 `docs/<功能>維護說明.md` 寫好或更新手冊，跟程式碼一起版控。若同一功能已有維護手冊，更新既有文件。

寫給日後接手的人和 AI。優先說明什麼情況會壞、為什麼採取目前做法，以及環境或實作變動後會連帶影響什麼。

## 章節

依功能規模取捨。小功能可以只寫第 1、4、5、7 節。省略沒有內容的章節。

| 節 | 內容 |
| --- | --- |
| 1. 總覽 | 功能用途、上下游和主要流程。用簡圖或表格呈現。 |
| 2. 部署與網路 | 從使用者到資料庫或外部服務的實際路徑。 |
| 3. 設定 | 設定項、位置與影響。設定值一律用佔位符。 |
| 4. 環境變動會破壞什麼 | 受影響的功能、症狀、查法與處理方式。 |
| 5. 已知限制與妥協 | 技術取捨、代價、失效條件與確認方式。 |
| 6. 維運與排障 | 日誌位置、搜尋關鍵字、常見症狀及原因。 |
| 7. 測試 | 執行方式、涵蓋範圍與需手動驗證的項目。 |

## 部署與網路

依可查證的部署設定或執行證據，逐段記錄實際請求路徑。可能的節點包括 CDN／WAF、Gateway／反向代理、站台、資料庫及外部服務。記下各段由誰管理、TLS 在哪裡終結、轉送時新增或改寫的 header、有無路徑前綴，以及站台數量和執行環境。

程式庫和可取得的設定查不到關鍵基礎設施事實時，向使用者確認。仍查不到的項目標「未確認」，並寫明所需的設定、日誌或實際驗證方式。

## 環境變動會破壞什麼

| 變動 | 受影響的功能 | 症狀 | 程式碼或設定位置 | 怎麼查／怎麼修 |
| --- | --- | --- | --- | --- |

每列指出具體位置，例如讀取 header 的程式、設定回呼網址的位置，或存放程序內狀態的元件。已驗證的照實寫。重要但未驗證的標「未確認」並說明怎麼確認。只記錄跟該功能有關的變動。

| 變動 | 可查的連帶影響 |
| --- | --- |
| 增減或更換 proxy、CDN | 真實 IP 取得與轉送標頭信任設定、HTTPS 判斷、轉址、Cookie 的 Secure 屬性。 |
| 換網域、加路徑前綴 | Cookie 的 Domain 或 Path、CORS、OAuth 回呼網址白名單、固定的絕對網址。 |
| 一台變多台、加負載平衡 | 程序內 session、快取、速率限制、金鑰共用、排程重複執行。 |
| 嵌入 iframe、跨站呼叫 | SameSite、X-Frame-Options、CSP 的 `frame-ancestors`。 |
| 出口 IP、防火牆變更 | 對方白名單、資料庫與外部 API 的連線。 |
| 憑證更換或到期 | TLS 連線與簽章驗證。 |
| 時鐘、時區變更 | Token 有效期及排程時間。 |
| 資料庫搬遷、帳號權限變更 | 連線字串、執行權限及跨庫查詢。 |
| Runtime、IIS 或作業系統升級 | 版本相容性及預設行為。 |

## 已知限制與妥協

| 項目 | 採用的做法及放棄的選項 | 代價或風險 | 失效條件及確認方式 |
| --- | --- | --- | --- |

記錄技術理由與可觀察的失效條件。例如，若改成多台部署，查排程有無跨機器的鎖，並核對各台執行紀錄是否出現重複觸發。已知但尚未修正的問題，寫明影響範圍。
